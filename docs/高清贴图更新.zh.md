# 用户半身高清贴图更新

新版 GLB 已保存为 `sceneresource/user-head/UserCharacter_HD_Source.glb`。原始低分辨率检查副本保留在 `preview/model-review/user-head.glb`，模型检查页仍用于查看原始模型。

## 兼容性与原因

新旧 POSITION、NORMAL、TEXCOORD_0 与索引的访问器和二进制数据一致：3324 顶点、5174 三角形。贴图从 512×512 增至 1024×1024。无需重新适配头皮、发根、碰撞或整体旋转。

此前半身颜色被采样到顶点，衣领和皮肤在三角形内部插值，增加图片分辨率仍不能消除这个问题。现在身体按原 UV 在片元阶段采样高清 JPEG，保留原图字节；仅脸部使用干净肤色以去掉原固定五官，再显示独立动态五官。

干净肤色过渡使用角色局部 Y=1.039～1.1095（源 Y=0.43～0.46），位于衣领上方，随完整角色旋转。眉毛、眼睛、嘴巴的独立图集与惊讶表情修复保持不变。

## 运行时与复现

- `python scripts/update-user-texture.py`：先验证新旧几何、法线、UV、索引完全兼容，再提取 JPEG、更新运行时 UV。
- `node scripts/build-core.cjs`：更新浏览器资源副本。
- 主场景与两种表情方案均采用相同贴图和肤色过渡。
- Cocos 使用 `assets/resources/effects/UserCharacter.effect`，资源路径集中在 ResourcePaths；材质异步加载失败时回退顶点色。头型切换复用已加载材质，销毁时清理材质，不增加逐帧资源加载。
- `adapt-user-head.py` 重建时保留原 UV，采样新版贴图生成回退顶点色。已有 `UserHead_Adapted.blend`、`UserCharacter_Adapted.glb` 是此前顶点色适配的历史输出，本次没有重导出；当前运行时以 JSON、JPEG、effect 为准。

JPEG 为 162249 字节（约 158.4 KiB）；RGBA8 解码基础层约 4 MiB，完整 mip 链约 5.33 MiB。浏览器为每个 WebGL 上下文创建一份纹理并生成完整 mip 链，未增加角色网格数。Cocos 使用正常资源导入，未手工创建 meta，未仅开启 mip 采样而使用缺失 mip 的纹理。

## 验证边界

独立浏览器检查衣领、袖口、正侧背面、表情和头型切换。类型检查与自动测试另行运行。新资源仍需由 Creator 正常导入，Cocos effect 编译、微信真机外观与显存尚需引擎内验收；浏览器结果不替代真机。
