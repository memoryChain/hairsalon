# 用户头模检查

日期：2026-09-19。来源：用户提供的 `tripo_convert_c8a38e4a-48ed-432c-9721-7319e48c95e9.glb`。

2026-09-20 更新：三项适配已完成并接入，结果见 [用户头模适配](用户头模适配.zh.md)。下文保留适配前的检查记录。

## 判断

可以保留这个模型的头部几何作为游戏角色基础，不必照着重建。它是光头卡通半身像，脸型、鼻子、耳朵、颈部和肩部已有结构；静态 GLB 可直接显示。接入当前剪发与动态表情仍需要适配，不能把静态显示成功当成玩法已接好。

本轮只创建独立检查副本与预览 `/model-review/index.html`，原 GLB 未修改，理发和表情场景未替换。Blender MCP 无法连接，因此本轮通过 GLB 二进制结构分析及独立 WebGL 原贴图/纯色视图核查，没有宣称做过 Blender 修改或 Cocos 验收。

## 实测结构

- 5,174 三角面、3,324 导出顶点；按位置六位小数合并后为 2,624 点、一个连通整体。
- 单节点、单网格、单 primitive、单材质；没有独立眼球、没有蒙皮骨骼、动画或 Morph targets。
- 一张 512×512 RGB JPEG 底色贴图，含眼白、瞳孔、眉毛、嘴型及衣服；有 UV，无外部贴图依赖。
- 合并位置后的边界边 76 条，都位于 Y=0 的身体底部；检测到的非流形边为零、退化三角面为零。此统计不等同于全面自相交检查。
- 原坐标 Y 朝上、角色面朝 +X，当前原型面朝 +Z；接入需统一朝向、比例与头部旋转中心。

具体尺寸和字节数见 `用户头模检查.json`。

## 外观与表情适配

原贴图视图与纯色视图对比确认：眼睛、眉毛主要来自贴图；鼻子、耳朵及嘴唇附近有真实几何。嘴部存在固定口型的小起伏，需要局部调整或按原轮廓设计表情区域，避免贴图笑嘴上叠着原来的嘴唇轮廓。

建议保留头部主形体与耳鼻，清理肤色底图中的固定眼眉口图案；补一套连续面部坐标/遮罩，使左右瞳孔、眼睑、眉毛、嘴型能独立控制。现有 UV 可用于保留外观，但图块较碎，直接平移原眼睛 UV 会连带眼白/皮肤，不能替代独立瞳孔层。

512×512 对整张半身像可以作为原型起点，近景五官边缘已有像素感；仅放大图片不会增加有效细节。后续优先给脸部增加有效像素、重新绘制干净五官，而非先增加模型面数。

## 理发接入步骤

1. 保留源文件，工作副本统一朝向、尺度、头中心；头与颈/身体需明确分离或绑定，避免转头带着整个半身像旋转。
2. 在完整头部上提取独立头皮区域和真实表面绑定，按该头型设置发际线、法线、碰撞包络；不能直接复用旧头模的顶点索引。
3. 接入清理后的肤色与五官图集，复用 FaceExpressionController 的视线、眨眼、眉毛、嘴型通道。
4. 先验证一款短发和一款长发的根部贴合、梳理碰撞、剪剃，再扩展其他预设。
5. 最后检查 Cocos 导入、材质深度与遮挡、微信包体和设备性能。现有原型的 JSON/顶点色渲染并不会自动导入 GLB 贴图，仍需更新资源与渲染接入。

结论：推荐直接利用现有几何做适配。无需为当前贴图表情增加完整面部骨骼，也不建议仅为数字好看把 5,174 面细分成高面网格。
