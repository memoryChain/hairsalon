# 营业流程与明星发型评分

日期：2026-09-20。单人离线原型，Cocos 入口和独立 WebGL 预览共用流程、目标与评分逻辑。未启动 Creator，未做微信真机验收。

## 可玩流程

客人进店 → 提出要求 → 准备开剪 → 理发 → 整理展示 → 评分 → 重试或下一位。

- 默认进入营业模式；独立预览 `/?sandbox=1` 保留原发型自由实验入口。
- 漫画保持同一画面，点击屏幕任意位置推进下一句气泡对白；移除分格编号、进度点和下一格按钮，最后一句后再次点击进入理发。直接实时展示现有完整角色模型（当前资源为带肩膀和衣服的上半身），保留原贴图、头发、眨眼和表情。人物通过带指向尾巴的气泡说话，提出发型要求时在气泡内展示明星照片。没有裁出头像或新增老板模型。
- 独立预览把原 WebGL 画布移入当前漫画格；Cocos 使用同一个三维相机输出 RenderTexture 到漫画 Sprite。镜头按完整模型与头发的包围范围取景，进入理发后恢复原镜头，不重建角色或模拟。
- 26 个任务（20 位明星、6 种动物）随机出场，一轮内不重复，跨轮避免连续遇到同一位。目标与初始造型分开：每个固定目标配置多个兼容起点，包含跨预设和明显加长的变化；同一初始造型也能服务多个目标。再次遇到同一目标时避免抽中上次起点，重试恢复本次组合。
- 明星照片随包存储、角落常驻，点击放大照片并展示客人要求。结算左侧直接显示同一明星照片，右侧显示玩家作品；切换角度只作用于作品。玩家界面不再展示游戏目标角色图，照片加载失败时也不会回退到游戏角色。评分内部仍使用预设的简化发型几何，未增加照片识别。
- 现有剪刀、手／梳理、吹风、剃光直接复用，普通工具切换不重建模型。营业时不显示自由换发型、即时重置或头皮诊断入口。
- 一次完成只结算一次，结算期间停止接受操作；0.6 秒展示过渡后读取定型结果。重试恢复同一任务，下一位客人才更换任务。
- 手梳触发开心，吹风与普通剪切触发惊讶，大面积剪得过短触发难过；情绪反应有冷却。结算表情由得分决定。

## 目标与评分

目标实例始终从订单指定的标准预设调用 PlaneHairCutter 生成，不随抽到的初始造型改变。左右收窄，底边根据每缕最低发根分档，保留发根保护间距，避免统一高切面遗留后颈长束。结果保留真实切口和封口，评分目标缓存最多三组任务，超过后淘汰最早缓存。兼容池每个组合都通过实际剪切后的高分可达回归：绵羊组合至少 85 分，其余至少 90 分；这验证几何层的可剪性，不等于玩家能方便地逐刀完全复刻，任务手感仍需试玩校准。

评分读取 `cutMesh || fiberMesh` 的实际存活面及插值绑定，排除碎发。FiberRig 的可选 stable 求值读取局部定型曲线，使用零头部姿态，排除临时风位移、旋转惯性，不改模拟位置、上一帧位置、曲线或风场。默认实时求值路径保持原有行为。

总分：50% 外形 + 30% 长度包络 + 20% 走向，三项均为 0–100。最终造型相同就同分，不读取入场分、操作次数或改造进度，不对未操作情况强制归零。90/70/45 对应三／二／一星，低于 45 为零星。初始造型在内容配对阶段筛选：按同一正常评分不高于 59、轮廓分不高于 65，并检查实际修剪可达高分。这些条件不裁剪或扣减玩家的结算得分。

- **外形**：固定头部中心和 2.9 世界单位取景框，正／右／背／左各生成 96×96 遮罩。头部深度遮挡参与判断。每向为 65% IoU 加 35% 双向邻域匹配率（一个像素容差），四向等权。
- **长度包络**：每缕实际剩余网格距发根最远顶点的距离，按发根面积权重汇总到刘海、左侧、右侧、后脑、顶部五个公共区域，再比较区域均值。0.035 世界单位容差。跨预设不按发束编号硬配对。这是空间长度包络，不是曲线弧长，强弯曲与内部层次仍可能产生评价偏差。
- **走向**：上述根到远端向量在五个公共区域的加权均值夹角，0.12 弧度容差；空发束单独处理。区域内部差异主要由四向轮廓补充判断。
- **反馈**：刘海、左右、后脑、顶部的长度差异选主要问题，附轮廓或走向建议。左右为角色自身的局部坐标，正面看时与屏幕左右相反。
- 发色、照片脸型、照明、背景不计分。没有视觉大模型、图像识别或联网评分。权重和容差是初步标定，不等同人的审美判断。

结算作品图为 512×512，按存活头发与完整现有角色（肩膀、衣服、身体）范围独立取景，保留 12% 余量；只在第一次查看对应角度时生成，最多缓存四张（含深度/遮罩/RGBA 约 9 MiB），重试或下一位时清空。目标角色肖像不再生成，评分仍使用固定尺度的 96×96 遮罩。销毁旧 UI 纹理与 SpriteFrame；对白切换只更新文字与照片显隐，保持模型画布、气泡位置、镜头与 Cocos Sprite 不变；漫画在 568×436 的显示区域复用 1136×872 实时渲染纹理。参考照片由 Cocos 资源系统管理。模型、模拟、工具不因面板切换重建。完整评分只在完成结算时执行；切发情绪的几何采样最多约一次每 1.1 秒。桌面耗时不能作为微信性能验收。

## 开场漫画实时画面抗锯齿（2026-09-20）

开场使用 Camera → RenderTexture → Sprite，与 CPU 结算图是两条路径。原纹理按 568×436 显示尺寸生成，没有足够的子像素覆盖，细眉和眼白边缘容易断续。现改为 1136×872 双倍采样、线性缩小、禁用 mip 过滤，显示布局与镜头取景比例保持不变。纹理和 SpriteFrame 跨对白复用，只在尺寸或目标节点变化时处理绑定；保持实时模型、眨眼和表情。最长纹理边限制为 1536，正常漫画颜色与深度缓冲合计约 7.6 MiB，微信真机性能待验收。

独立预览漫画也使用相同的双倍尺寸策略，保留 WebGL 自带抗锯齿；进入理发后恢复原设备像素比策略。尺寸变化只在阶段变化或 ResizeObserver 回调时处理，不每帧重建画布。自动检查覆盖双倍尺寸、纵横比与上限；Creator 未自动启动，独立预览不能代替 Creator 和微信验收。

验证：npm test 270 项中 269 项通过，唯一失败仍为原 physics 配置审计；typecheck、fonts:build、fonts:check 及 diff 空白检查通过。独立预览实测漫画 347.78×481 显示区域对应 696×962 画布，对白切换尺寸稳定，进入理发后恢复 1280×720，无控制台错误。日志 .cache/salon-flow/tests-comic-aa.log。
